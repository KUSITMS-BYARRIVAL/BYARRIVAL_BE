# 부하 테스트

Docker만 있으면 됩니다. 전용 컨테이너에 가상 데이터를 넣고 k6를 돌린 뒤 모두 지웁니다. AI·푸시·디스코드는 호출하지 않고, 로컬이 아닌 주소에는 실행되지 않습니다.

```bash
./perf/run.sh load
```

| 종류 | 내용 |
|---|---|
| `smoke` | 15초. 시나리오가 깨지지 않았는지 확인 |
| `load` | 3분 30초. 출근 시간대 가정 부하(조회 초당 2회 × API 7번, 노선 시작 초당 1명) |
| `stress` | 5분. 조회를 초당 2→10회로 올려 한계를 찾음 |

- 통과 기준: 전체·API별 p95 500ms, 전체 p99 1초, 실패 1% 미만, 못 보낸 반복 0회. 통과하지 못하면 0이 아닌 값으로 끝납니다.
- 환경 변수: `USERS`(기본 5000), `RATE`(load의 초당 조회 반복), `P95_MS`(기본 500), `KEEP=1`(끝나고 컨테이너를 남김)
- 결과는 `perf/results/<종류>.md`에 남고 커밋하지 않습니다.
- 가정: 회원 5,000명, 하루 노선 2,000건, 30일치. 앱 CPU 2개·메모리 1.2GB, DB CPU 1개·768MB. 운영 실측이 아니므로 절대값보다 변경 전후 비교에 씁니다.
- 결과는 이 컴퓨터 상태에 따라 흔들립니다(같은 설정에서 전체 p95가 54ms와 990ms로 나온 적이 있음). 비교할 때는 설정을 번갈아 여러 번 잽니다.

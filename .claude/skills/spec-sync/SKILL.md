# /spec-sync

## 원본

- 노션 페이지: https://app.notion.com/p/kyungsooko/3eea151fdd4c80eea86bd3712bb1ad46 (상단에 변경 이력 표가 있다. 동기화 보고에 함께 참고한다.)
- 앱 기능명세서 데이터 소스: `collection://082a151f-dd4c-8360-b659-0770e9fa1966`
  - 컬럼: 기능 ID, 기능 그룹, 세부 그룹, 기능명, 우선순위, 기능 설명, 입력값, 처리 로직, 출력값, 예외 처리, 비고
- 어드민 기능명세서 데이터 소스: `collection://c61a151f-dd4c-8276-a509-87f6f498459a`
  - 컬럼: 기능 ID, 기능 그룹, 세부 그룹, 이름(기능명), 우선순위, 기능 설명, 입력값, 처리 로직, 출력값, 예외 처리, 비고
- 페이지 안의 데이터 소스가 바뀌었을 수 있으니 먼저 노션 페이지를 fetch해 위 두 데이터 소스가 맞는지 확인한다. 다르면 페이지의 데이터 소스를 쓰고 이 파일을 고친다.

노션 연결이 없으면 멈추고 사용자에게 노션 MCP 연결을 요청한다.

## 절차

1. 노션 MCP로 두 데이터 소스의 전체 행을 `기능 ID` 순으로 조회한다.
2. 기능 그룹별로 파일에 나눠 쓴다.

   | 기능 그룹 | 파일 |
   |---|---|
   | 공통 | `common.md` |
   | 온보딩 | `onboarding.md` |
   | 홈 · 탑승 | `home.md` |
   | 뉴스 이용 | `news.md` |
   | 콘텐츠 탐색 · 기록 | `archive.md` |
   | 마이 · 설정 | `my.md` |
   | 콘텐츠 관리 | `content-admin.md` |
   | 어드민 기능명세서 전체 (어드민 공통·기사 관리·에디터 픽·회원 관리·알림 · 공지) | `admin.md` |

   새 기능 그룹이 생기면 파일 이름을 제안하고 사용자 확인 후 만든다. `CLAUDE.md`의 파일 표도 함께 고친다.
3. 각 파일의 형식은 기존 파일을 따른다.
   - 머리말: 출처, 동기화 날짜(오늘), "직접 수정하지 말고 `/spec-sync`로 갱신"
   - 세부 그룹별 `##`(`onboarding.md`는 `##` 없이 기능마다 `- 세부 그룹:` 줄, `admin.md`는 기능 그룹별 `##`에 `- 세부 그룹:` 줄), 기능별 `### <기능 ID> <기능명> \`<우선순위>\``
   - 설명·입력·처리·출력·예외·비고 항목. 번호가 매겨진 처리 로직은 번호 목록으로 쓴다.
   - 내용은 원문 그대로 옮기고 요약하거나 고치지 않는다.
4. `git diff .claude/spec/features/`로 바뀐 기능 ID를 정리해 보고한다.
   - 추가·삭제·변경된 기능 ID
   - 이미 구현된 코드에 영향이 있는 변경 (해당 도메인 패키지가 있는지 확인)
   - "확정 필요"였다가 확정된 항목이 있으면 `.claude/spec/roadmap.md`의 미확정 목록에서 지운다.
5. 커밋은 하지 않는다. 사용자가 원하면 `docs: 기능명세서 동기화 (YYYY-MM-DD)`로 커밋한다.

# 온보딩 (ONB)

> 출처: 노션 「도착까지 기능명세서」 · 동기화 2026-11-10
> 직접 수정하지 말고 `/spec-sync`로 갱신합니다.

### ONB-01 서비스 시작하기 `P0`
- 세부 그룹: 인트로
- 설명: 인트로에서 서비스 이용을 시작한다.
- 입력: 시작 CTA
- 처리: 인증 상태를 확인하고 로그인 또는 다음 온보딩 단계로 이동한다.
- 출력: 로그인/온보딩 화면
- 예외: 중복 클릭 방지
- 비고: -

### ONB-02 소셜 로그인 `P0`
- 세부 그룹: 로그인
- 설명: 소셜 계정을 이용해 로그인 또는 회원가입한다.
- 입력: Provider(카카오/Apple), 인증 Token
- 처리: 인증 후 기존 회원 여부를 조회한다. 신규 회원이면 계정을 생성하고 기존 회원이면 사용자 데이터를 불러온다. 탈퇴 후 6개월 이내의 동일 소셜 계정이면 신규 계정을 생성하되 보관 중인 프로필·설정과 이용 이력을 모두 복원하고(MY-10), 온보딩 단계를 건너뛰어 온보딩 완료 상태로 홈으로 이동한다. 6개월이 지났으면 이력 없이 신규 가입으로 처리해 온보딩을 진행한다.
- 출력: 사용자 ID, 신규 회원 여부
- 예외: 인증 취소·실패 시 현재 화면 유지 및 오류 안내
- 비고: Provider: 카카오 로그인(Apple 로그인 병행). 재가입 판별은 소셜 계정 식별자 기준(제안). 복원된 회원은 온보딩 생략.

### ONB-03 약관 동의 `P0`
- 세부 그룹: 약관
- 설명: 서비스 이용에 필요한 약관 동의를 받는다.
- 입력: 약관별 동의 상태
- 처리: 전체 동의 및 개별 동의를 지원하며 필수 약관이 모두 동의된 경우에만 다음 CTA를 활성화한다.
- 출력: 약관 동의 정보
- 예외: 필수 약관 미동의 시 다음 진행 불가
- 비고: 필수/선택 구분

### ONB-04 닉네임 설정 `P0`
- 세부 그룹: 사용자 정보
- 설명: 서비스에서 사용할 닉네임을 입력한다.
- 입력: 닉네임
- 처리: 입력 규칙을 검증하고 유효한 경우 사용자 정보에 저장한다.
- 출력: 닉네임
- 예외: 유효성 미충족 시 오류 노출
- 비고: 글자수/금칙어 확정 필요

### ONB-05 이동 상황 선택 `P0`
- 세부 그룹: 이동 설정
- 설명: 주 이동 상황을 직장인·학생·기타 중 선택한다.
- 입력: 이동 유형
- 처리: 단일 유형을 선택해 사용자 프로필에 저장하고 이후 유형별 카피에 사용한다. 1차 추천 로직(RIDE-04)에는 반영하지 않는다.
- 출력: 이동 유형
- 예외: 미선택 시 다음 진행 불가
- 비고: 유형별 카피 변경. 추천 조건 반영은 추후 개인화 고도화 시 검토.

### ONB-06 이동 시작 시각 설정 `P0`
- 세부 그룹: 이동 설정
- 설명: 사용자의 평소 이동 시작 시각을 설정한다.
- 입력: 이동 시작 시각
- 처리: 선택 시각을 기본 이동 시작 시각으로 저장한다.
- 출력: 이동 시작 시각
- 예외: 미입력 시 다음 진행 불가
- 비고: 유형별 출근/등교/출발 카피

### ONB-07 이동 알림 사전 안내 `P1`
- 세부 그룹: 알림 설정
- 설명: 이동 시작 전 알림 제공 기능을 안내하고 알림 권한 설정을 유도한다.
- 입력: 알림 동의 여부
- 처리: 사용자가 동의하면 OS 알림 권한을 요청하고 결과를 저장한다.
- 출력: 알림 권한 상태
- 예외: 권한 거부 시 알림 없이 진행 가능
- 비고: 알림 제공 시각 정책 확인

### ONB-08 기본 이동 시간 설정 `P0`
- 세부 그룹: 이동 설정
- 설명: 이동 중 콘텐츠 소비에 사용할 기본 시간을 설정한다.
- 입력: 이동시간(분)
- 처리: 설정 가능한 범위 내에서 이동시간을 선택하고 사용자 정보에 저장한다.
- 출력: 기본 이동시간
- 예외: 범위 외 값 선택 제한. 미설정 시 다음 진행 불가(필수).
- 비고: 요일별 설정(MY-07)이 없을 때 사용하는 기본값. 노선 생성 시 목표 시간(T)으로 활용(RIDE-04).

### ONB-09 관심 분야 선택 `P0`
- 세부 그룹: 관심 분야
- 설명: 추천받고 싶은 뉴스 관심 분야를 복수 선택한다.
- 입력: 카테고리 ID 목록
- 처리: 관심 분야를 복수 선택하고 완료 시 사용자 프로필에 저장한다. 카테고리는 8개(건강·생활 / 연예·문화 / 정치·사회 / 경제·금융 / 과학·환경 / IT·기술 / 세계·국제 / 스포츠)로 노출한다(하위 세부 항목 포함, 기준표는 RSS-07 참조).
- 출력: 관심 분야 목록
- 예외: 1개 미만 선택 시 완료 불가
- 비고: 최소 1개 이상 선택 (필수)

### ONB-10 온보딩 완료 `P0`
- 세부 그룹: 완료
- 설명: 필수 사용자 설정을 저장하고 최초 온보딩을 완료한다.
- 입력: 유형, 시각, 시간, 관심 분야
- 처리: 필수값(이동 유형, 이동 시작 시각, 기본 이동시간, 관심분야 1개 이상)의 저장 여부를 확인하고 사용자 온보딩 상태를 완료로 변경한 뒤 홈으로 이동한다.
- 출력: 온보딩 완료 상태, 홈
- 예외: 저장 실패 시 현재 화면 유지
- 비고: -

### ONB-11 직군 선택 `P0`
- 세부 그룹: 직군
- 설명: 이동 유형에 맞는 문구로 직군(학생은 희망 직군)을 최대 2개까지 선택한다.
- 입력: 이동 유형, 직군 코드(12종) 최대 2개
- 처리: 12개 직군(기획·마케팅 / 인사·총무·법무 / 금융·회계 / IT개발·데이터 / 디자인 / 영업·서비스·상담 / 제조·물류·건설 / 의료 / 연구·교육 / 미디어·문화·스포츠 / 공공·복지 / 기타·프리랜서) 중 최대 2개를 선택(1개 이상 필수)하여 프로필(job_group)에 저장한다. 직장인은 "어떤 일을 하고 계신가요?", 학생은 "어떤 직무를 희망하시나요?"로 문구를 분기한다. 선택한 직군은 모두 홈 "지금 출근길에서 많이 봐요"의 직군 칩으로 노출한다(HOME-05). 이미 2개를 선택한 상태에서 3번째를 선택하면 선택되지 않고 "직군은 최대 2개까지 선택할 수 있어요" 안내를 노출한다. 선택된 카드는 체크박스 등으로 명확히 구분한다. 직군을 왜 받는지 설명 문구는 화면 상단에 노출한다(디자인).
- 출력: 직군 코드 목록(1~2개)
- 예외: 미선택 시 다음 진행 불가 / 저장 실패 시 토스트 안내 후 재시도
- 비고: 사람인 직무 분류 21개를 관심 뉴스가 비슷한 12개로 통합. 세부 코드는 추후 분리 가능하도록 유지. 기타 유형 문구는 직장인과 동일(미확정). 직군은 최대 2개까지 선택한다. 저장 구조는 job_group 단일값에서 목록(최대 2)으로 변경한다. 기존 단일값 사용자는 그 값 1개를 목록의 첫 항목으로 자동 이전한다(마이그레이션).

### ONB-12 근무 지역 선택 `P0`
- 세부 그룹: 지역
- 설명: 이동 유형에 맞는 문구로 근무·통학·주 이동 지역(시/도 → 시/군/구)을 1개 선택한다.
- 입력: 이동 유형, 시/도, 시/군/구, 검색어
- 처리: 17개 시/도를 선택하면 해당 시/군/구 목록이 노출되고, 단일 선택하여 프로필(region_sido, region_sigungu)에 저장한다. 직장인은 "근무 지역", 학생은 "통학 지역", 기타는 "주 이동 지역"으로 문구를 분기한다. 검색으로 지역을 찾을 수 있다. 현재 버전에서는 수집만 하며 홈 노출 기준으로 사용하지 않는다. "○○전체"(예: 서울전체·경기전체) 선택지는 제공하지 않으며 시/군/구 단위로만 선택한다. 세종은 시/군/구가 없으므로 "세종특별자치시" 단일 항목으로 선택한다.
- 출력: 시/도 코드, 시/군/구 코드
- 예외: 미선택 시 다음 진행 불가 / 저장 실패 시 토스트 안내 후 재시도
- 비고: 서울·경기 외 전 시/도 동일 구조. 기존 학교 위치 입력 화면과의 대체 여부 미확정. 지역을 왜 받는지 설명 문구는 화면 상단에 노출한다(디자인).

### ONB-13 지역 데이터 확장 대비 `P1`
- 세부 그룹: 지역
- 설명: 유저가 쌓인 뒤 지역을 묶어서 노출할 수 있도록 원본 지역 데이터를 그대로 보관한다.
- 입력: 시/도, 시/군/구
- 처리: 구 단위는 유저 수가 적어, 우선 시/군/구 원본 코드를 그대로 수집한다. 추후 그룹 기준(권역·생활권 등)은 별도 매핑 테이블로 관리하고 변경 이력을 남긴다. 그룹화 기준은 유저 수가 쌓인 뒤 결정한다. "○○전체" 선택지는 제공하지 않으므로 전체 단위 값은 저장하지 않는다.
- 출력: -
- 예외: -
- 비고: 확장 가능성 항목. 현재 버전 노출 없음.

## RSS 소스

### RSS-01 RSS Feed 관리 `P0`
- 설명: 서비스에서 사용할 언론사 RSS Feed를 등록·관리한다.
- 입력: 언론사명, Feed URL, 카테고리
- 처리: Feed 정보와 활성 상태를 저장하고 활성 Feed만 수집 대상으로 사용한다.
- 출력: Feed 정보
- 예외: 접근 불가 Feed 비활성 처리
- 비고: 사용 허가 Feed만 사용

## RSS 수집

### RSS-02 RSS 기사 수집 `P0`
- 설명: 활성 RSS Feed에서 신규 기사 데이터를 주기적으로 수집한다.
- 입력: Feed URL
- 처리: 매일 1회 전일 23:45에 활성 Feed를 호출해 RSS Item을 조회한다. 같은 배치에서 수집 → 정제 → 카테고리 매핑 → 카테고리별 최신 발행순 최대 60건 선별 → 난이도 배정(HARD 30·EASY 30) → AI 요약 생성(기사별 배정 난이도로 1회) → 예상 읽기시간 계산까지 처리하며 23:59까지 완료한다. 마감 시각까지 처리되지 않은 기사는 해당 서비스일 후보에서 제외한다.
- 출력: RSS Item 목록
- 예외: 개별 Feed 실패가 전체 수집을 중단하지 않도록 처리한다. 배치 단위 실패 시 마감 시각(23:59) 전까지 재시도하며, 끝내 실패하면 당일 후보 0건으로 추천 불가 화면이 노출된다.
- 비고: 수집 주기: 1일 1회, 23:45 시작·23:59 완료(확정). 수집량: 카테고리별 난이도(HARD/EASY)당 최대 30건(카테고리당 최대 60건), 초과 시 최신 발행순(확정). 난이도 배정은 선별된 기사에 랜덤 균등 배정(제안), 60건 미만이면 가능한 한 절반씩 배정. 카테고리 수 × 최대 60건의 AI 호출을 마감 안에 처리해야 하므로 병렬 호출 필요. RSS 본문 제공 범위와 사용 허락은 언론사와 협의 중.

### RSS-03 RSS 데이터 파싱 `P0`
- 설명: RSS Item에서 서비스에 필요한 기사 데이터를 추출한다.
- 입력: RSS Item
- 처리: 제목, URL, description/content, 발행일, GUID, 카테고리 등을 공통 데이터 구조로 변환한다.
- 출력: 정규화 기사 데이터
- 예외: 필수값 누락 시 저장 제외/오류 기록
- 비고: 언론사별 구조 차이 대응

### RSS-04 기사 중복 검사 `P0`
- 설명: 기존 수집 기사와 신규 기사를 구분한다.
- 입력: GUID, originalUrl
- 처리: 매일 수집 배치마다 GUID 또는 URL을 DB와 비교해 동일 기사 존재 여부를 판단한다.
- 출력: 신규/중복 여부
- 예외: GUID 없으면 URL 사용
- 비고: GUID 우선. 매일 배치마다 수행.

- 예외: 정제 실패 시 Raw 유지

### RSS-07 카테고리 매핑 `P0`
- 설명: 언론사별 기사 카테고리를 서비스 관심 분야로 변환한다.
- 입력: RSS category, source
- 처리: 내부 카테고리 규칙과 비교해 서비스 카테고리를 부여한다.
- 출력: internalCategory
- 예외: 매핑 불가 시 기타/검수 대상
- 비고: 매핑 기준표 필요

### RSS-09 예상 읽기시간 계산 `P0`
- 설명: 정제된 기사 본문 글자수를 기준으로 기사별 예상 읽기시간을 계산해 사전 저장한다.
- 입력: articleId, 정제 본문
- 처리: 정제 본문 글자수(공백 포함) ÷ 500(자/분)으로 예상 읽기시간(분)을 계산해 기사와 함께 저장한다. 소수점 포함으로 저장하고, 화면 표시와 노선 총 시간 표시는 올림 처리한다. 읽기 속도는 사용자와 무관한 고정값이며 설정값으로 관리한다.
- 출력: 예상 읽기시간(분)
- 예외: 본문이 없거나 정제에 실패해 산출 불가하면 추천 가능 조건 미충족으로 추천에서 제외(RSS-08)
- 비고: 시간 기준은 요약이 아니라 원문 본문 글자수. RSS가 본문 전체를 제공하는지 확인 필요(발췌만 제공하면 읽기시간이 부정확). 읽기 속도 근거: 국내 성인 묵독 속도 연구(평균 약 550자/분, 20~30대, 쉬운 문장 기준)를 뉴스 문장 난이도를 고려해 500자/분으로 보수 적용

## 추천 후보 관리

### RSS-08 추천 가능 기사 관리 `P0`
- 설명: 수집·가공이 완료된 기사 중 추천에 사용할 기사 후보군을 관리한다.
- 입력: articleId, 발행시각, 서비스 대상일, 카테고리, AI 가공 상태, 난이도 태그(HARD/EASY), 예상 읽기시간
- 처리: 아래 조건을 모두 충족한 기사만 추천 가능 상태로 둔다: ① 서비스 대상일 배치(전일 23:45 수집분) ② 카테고리 매핑 완료 ③ 배정된 난이도(HARD 또는 EASY)로 3문장 요약 생성 완료(AI-02) ④ 예상 읽기시간 산출 완료 ⑤ 카테고리별 난이도당 최대 30건 이내. 서비스 대상일이 지나면(당일 24:00) 추천 불가 상태로 전환하며, 하루가 지난 기사는 신규 노선에 제공하지 않는다. 이미 생성된 노선의 스냅샷에는 영향을 주지 않는다.
- 출력: 추천 가능 상태
- 예외: 필수 데이터 누락/유효기간 만료 기사는 추천 제외
- 비고: 기사 유효기간: 서비스 대상일 당일 1일로 확정 (카테고리별 구분 없음)

## AI 요약

### AI-01 AI 3줄 요약 생성 `P0`
- 설명: 정제된 기사 내용을 AI로 3문장 요약한다. 기사마다 배정된 요약 난이도(EASY 또는 HARD) 하나로 1회 생성한다.
- 입력: articleId, 기사 제목, 정제 본문, 배정된 요약 난이도(EASY/HARD)
- 처리: AI-06 프롬프트로 기사 1건당 배정된 난이도로 1회 호출해 3문장 요약을 생성한다. 기사별 난이도는 수집 배치에서 배정하며 AI가 판정하지 않는다. 호출은 기사 단위로 병렬 처리한다.
- 출력: title, difficulty, summary(3문장)
- 예외: 생성 실패 시 미노출 및 재처리(AI-05)
- 비고: 서비스 기사 본문에 활용. 각 문장은 공백 포함 30자 이내. 배정된 난이도가 기사의 난이도 태그가 되어 노선 생성 시 컨디션별 HARD:EASY 비율로 기사를 고르는 데 사용(RIDE-04).

### AI-02 AI 요약 저장 `P0`
- 설명: 생성된 난이도별 요약을 기사와 연결해 저장한다.
- 입력: articleId, 요약 난이도, 요약 결과(JSON)
- 처리: 서버에서 응답을 검증한다(JSON 파싱 가능, summary 정확히 3개, 각 문장 공백 포함 30자 이내, title·difficulty가 입력값과 동일). 통과하면 articleId에 요약과 난이도 태그를 저장하고 완료 상태를 기록한다. 프롬프트에 글자수 검증 지시가 있어도 AI가 어길 수 있으므로 서버 검증은 필수이다.
- 출력: summary, 난이도 태그, 생성 상태
- 예외: 검증 실패·빈/비정상 응답은 실패 처리하고 재처리(AI-05)
- 비고: 기사당 배정된 난이도의 요약 1건을 저장하며, 요약이 완료되어야 추천 가능(RSS-08)

### AI-06 AI 요약 프롬프트 규격 `P0`
- 설명: 기사 요약 생성에 사용하는 AI 프롬프트와 입출력 규격을 정의한다. 프롬프트 전문은 노션 해당 행의 페이지 본문에 있다.
- 입력: title(기사 제목), article(기사 본문), difficulty(EASY 또는 HARD)
- 처리: 난이도는 AI가 기사에서 판정하는 값이 아니라 입력값이다. EASY는 처음 접하는 사람도 이해할 수 있는 쉬운 표현과 핵심 수치 위주, HARD는 기본 지식이 있는 독자 대상으로 전문용어와 구체적 수치를 보존하고 정보 밀도를 높인다. 요약은 정확히 3문장(1: 핵심 사건·변화, 2: 배경·원인·수치, 3: 결과·영향·전망)이며 각 문장은 공백 포함 30자 이내, 기사에 있는 정보만 사용한다.
- 출력: JSON {title, difficulty, summary[3]} (JSON 외 설명·마크다운 코드 블록 없음)
- 예외: 형식·글자수·개수 위반은 AI-02 검증 실패로 처리하여 재처리(AI-05)
- 비고: JSON 예시의 따옴표는 일반 따옴표(")를 사용할 것(곡선 따옴표 사용 시 파싱 오류 위험). HARD 요약은 30자 제한 안에서 정보 밀도를 유지하는지 샘플 검수 필요.

## 스몰토크

### TALK-01 스몰토크 생성 `P1`
- 설명: 수집된 인기 기사를 바탕으로, 대화 소재로 쓸 수 있는 스몰토크(한 줄 + 이어서 + 연결 기사)를 매일 자동 생성한다.
- 입력: 당일 수집·요약이 완료된 기사(제목, 원문, 카테고리, 원문 URL), 인기 기사 판단 기준값
- 처리:
  1. 서비스일 배치(23:45~23:59) 중 기사 수집·요약 완료 후 실행한다.
  2. 대상 선정: 수집된 기사 중 '인기 기사'를 카테고리별로 상위 순으로 선정해 카테고리당 최대 2건의 스몰토크를 생성한다(확정). [제안] 인기 기준 = 언론사 RSS/랭킹 노출 순위. 기준 데이터가 없으면 당일 수집 기사 중 최신 발행순으로 대체(서비스일 하루 기준).
  3. 기사 1건당 AI 호출 1회로 아래 구성의 스몰토크를 생성한다.
     - 한 줄(hook): 대화를 여는 한 문장. 인용부호 가능, 30자 이내 권장.
     - 이어서(follow-up): 한 줄을 받아 이어 말하는 1~2문장, 사실 기반.
     - 연결 뉴스: 기반 기사의 카테고리 · 제목 · 원문 URL.
  4. 중립성 규칙(프롬프트 + 서버 검증): 원문에 있는 사실·수치만 사용, 원문에 없는 추측·전망 단정 금지, 특정 정당·인물·기업·집단에 대한 평가·비하·조롱 표현 금지, 정치·종교·젠더·세대 갈등 소재는 생성 제외 또는 사실 전달만, 수치는 출처 기사 표기와 동일하게, 전망은 '~라고 해요/~라고 전해져요'처럼 출처 귀속 어투 사용.
  5. 서버 검증: JSON 파싱, 필수 필드(hook, followup) 존재, 글자 수 제한 이내, 금칙어·평가어 필터 통과, 원문 URL 존재. 실패 시 같은 기사로 최대 3회 재시도한다.
  6. 대체 생성: 3회 재시도 후에도 검증에 실패하면 해당 기사는 제외하고 같은 카테고리의 다음 순위 인기 기사로 대체해 다시 생성한다(재시도 포함 동일 규칙). 후보를 모두 소진하거나 23:59가 되면 그 카테고리는 확보된 건수(0~2건)만 제공한다.
  7. 저장: 스몰토크 본문, 기반 기사 ID, 원문 URL, 생성일(서비스일)을 저장한다.
  8. 유효: 서비스일 당일에만 노출한다.
- 출력: 스몰토크(hook, followup, 연결 기사 카테고리·제목·원문 URL, 서비스일)
- 예외:
  - 기반 기사가 숨김·원문 삭제 상태가 되면 해당 스몰토크도 비노출(대체 생성은 하지 않음).
  - 검증 실패 시 같은 카테고리의 다음 순위 기사로 대체 생성. 후보 소진·23:59 도달 시 확보된 건수만 제공.
  - 생성 가능한 스몰토크가 0건이면 홈·목록에서 해당 영역 미노출.
- 비고: 스몰토크는 노선(RIDE-04) 추천 대상이 아니며 난이도 배정을 하지 않음. 카테고리당 최대 2건(확정), 검증 실패 시 다음 순위 기사로 대체(확정). '인기 기사' 판단 기준·프롬프트 세부 규격은 확정 필요(제안값 표기).

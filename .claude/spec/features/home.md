## 홈

### HOME-01 오늘의 홈 조회 `P0`
- 설명: 사용자 정보와 당일 이용 상태를 기반으로 홈을 구성한다.
- 입력: 사용자 ID, 날짜
- 처리: 당일 노선, 기록, 스몰토크 추천 등을 조회하고 진행 중 노선이 있으면 이어보기 상태를 반영한다.
- 출력: 홈 데이터
- 예외: 일부 데이터 실패 시 영역 단위 오류
- 비고: -

### HOME-02 스트릭 표시 `P1`
- 설명: 사용자의 연속 서비스 이용 기록을 홈에 표시한다.
- 입력: 완주 기록
- 처리: 날짜별 완주 기록을 기준으로 연속 이용 일수를 계산한다.
- 출력: 스트릭
- 예외: 기록 없으면 초기 상태
- 비고: 완주 기준

### HOME-03 스몰토크 추천 미리보기 `P1`
- 설명: 홈에서 스몰토크 및 상식 용어 콘텐츠 일부를 제공한다. 홈 영역 명칭은 'Editor's Pick'에서 '스몰토크 추천'으로 변경한다.
- 입력: 스몰토크 추천 데이터
- 처리: 당일(서비스일) 노출 가능한 스몰토크(TALK-01 생성분)와 상식 용어 콘텐츠를 조회하여 일부를 카드 형태로 제공한다. 스몰토크 카드는 한 줄(hook) + 연결 뉴스 칩으로 구성하며, 카드 컴포넌트는 변경된 홈 카드 디자인을 따른다. 연결 뉴스 칩 탭 시 원문으로 이동한다.
- 출력: 콘텐츠 카드
- 예외: 콘텐츠가 없으면 해당 영역 미노출
- 비고: 상식 용어 콘텐츠는 진행하지 않음(보류).

## 출근 현황

### HOME-04 지금 출근하는 사람 표시 `P1`
- 설명: 현재 출근 중인 사용자 수를 홈에 표시한다.
- 입력: 앱 접속 이벤트, 사용자 ID
- 처리: 앱에 접속하면 +1, 1시간 동안 새 접속(갱신)이 없으면 -1로 집계한다. 사용자별 TTL 1시간 키로 관리해 1시간 내 중복 집계하지 않으며, 활성 키 개수를 표시 값으로 사용한다. 키는 사용자 ID 단위이므로 같은 사용자가 여러 기기로 접속해도 1명으로 센다. 실시간성 강조(LIVE 표시)는 디자인 변경이며 집계 로직은 변경하지 않는다.
- 출력: 출근 중 인원 수
- 예외: 집계 실패 시 카드 숨김
- 비고: 개발 편의를 위한 단순 기준. 추후 정교화 가능.

## 출근길 공감대

### HOME-05 지금 출근길에서 많이 봐요 (TOP3) `P0`
- 설명: 내 직군 또는 전체 기준으로 출근길에서 많이 저장된 뉴스 TOP3를 보여준다. 선택한 직군이 2개이면 두 직군을 모두 보여준다.
- 입력: 내 직군, 노선, 칩 선택(내 직군/전체) → 내 직군 목록(1~2개), 노선, 칩 선택(선택한 직군별/전체)
- 처리: 해당 노선에서 뉴스를 담은 사용자 수를 기사별로 집계해 내림차순(동률은 최신순)으로 3건 노출한다. "전체"는 전체 사용자 기준이다. 담은 사용자 수가 30명 미만이면 HOME-07(집계중 상태)을 노출한다. 지역 칩은 제공하지 않는다. 직군 칩은 사용자가 선택한 직군(최대 2개)을 모두 노출하고 전체 칩을 함께 제공한다(예: [직군A][직군B][전체]). 각 직군 칩은 해당 직군을 선택한 사용자 기준으로 집계한다. 칩별 N = 해당 칩 범위(직군/전체)의 사용자 중 해당 노선에서 기사를 1건 이상 담은 사용자 수(사용자 중복 제거)이며, 30명 미만 여부는 칩별로 판단한다. 2개 직군을 선택한 사용자는 두 직군 칩에 각 1명으로 포함되고 전체 칩에서는 1명으로 센다. 기사별 순위는 해당 칩 범위에서 그 기사를 담은 사용자 수로 정한다. 직군 칩 순서는 선택한 순서를 따른다.
- 출력: 뉴스 순위 3건
- 예외: 집계 실패 시 섹션 숨김
- 비고: N은 노선 단위이며 서비스일(KST 자정) 기준으로 매일 초기화한다. 기준 30명은 운영 초기 기준값이며 설정값으로 관리해 데이터가 쌓이면 조정한다. 직군 칩 순서는 저장된 직군 목록 순서를 따른다(MY-11).

### HOME-06 출근길 공감대 상세 (TOP10) `P1`
- 설명: 전체보기에서 선택한 기준의 뉴스 TOP10을 볼 수 있다.
- 입력: 칩 선택(내 직군/전체) → 칩 선택(선택한 직군별/전체)
- 처리: 홈에서 선택한 칩을 유지한 채 10건을 노출한다. 10건 미만이면 존재하는 건만 노출한다. 직군 칩은 홈과 동일하게 선택한 직군(최대 2개)을 모두 노출한다(HOME-05).
- 출력: 뉴스 순위 최대 10건
- 예외: 집계 실패 시 안내 문구 후 재시도
- 비고: -

### HOME-07 집계중 상태 (1등 갓생러) `P1`
- 설명: 집계 데이터가 부족할 때 곰돌이와 함께 안내 컴포넌트를 보여준다.
- 입력: 노선별 뉴스를 담은 사용자 수(N)
- 처리: N이 30명 미만이면 순위 대신 "축하합니다! 당신은 1등 갓생러"와 회색 "데이터를 집계중입니다"를 노출한다. 순위·수치는 노출하지 않으며, 컴포넌트 크기는 기존 순위 리스트 컴포넌트(353×224)를 넘지 않는다. 직군 칩별로 N을 판단하므로 칩마다 집계중 상태가 다를 수 있다.
- 출력: 집계중 안내 컴포넌트
- 예외: -
- 비고: 기준 30명은 운영하며 조정 가능.

## 탑승 시작

### RIDE-01 뉴스 탑승 시작 `P0`
- 설명: 사용자가 오늘의 뉴스 이용을 시작한다.
- 입력: 탑승 CTA
- 처리: 오늘 서비스일의 노선 여부를 확인한다. 진행 중 노선(생성 또는 진행 상태이며 만료 전)이 있으면 기존 노선으로 이동하고, 오늘 이미 완주했거나 만료된 노선이 있으면 새 노선을 만들지 않고 해당 결과 상태로 이동한다. 오늘 노선이 없을 때만 컨디션 선택으로 이동한다. 전날 시작한 노선도 만료 시각(생성일 다음 날 04:00) 전이면 진행 중 노선으로 본다. 오늘 노선이 생성되었으나 아직 시작하지 않은(CREATED) 경우에는 후보 카드 선택 화면(RIDE-08)으로 이동해 담아 둔 카드 상태를 그대로 보여준다.
- 출력: 컨디션/기사 화면 / 후보 카드 선택 화면
- 예외: 노선은 서비스일당 1회만 생성 가능하며, 이미 노선이 있으면 신규 생성 대신 기존 노선으로 이동
- 비고: 핵심 CTA

### RIDE-02 진행 중 노선 이어보기 `P0`
- 설명: 중단했던 노선을 마지막 진행 지점부터 이어본다.
- 입력: routeId
- 처리: 노선 생성 시 고정 저장된 스냅샷(기사 목록·순서·기사별 배정 난이도) 기준으로 현재 기사와 진행 상태를 복원한다. 설정 변경이나 기사 유효기간(당일) 경과와 무관하게 노선 만료 시각(생성일 다음 날 04:00)까지 유지한다. 스냅샷에는 후보 카드 풀과 사용자가 담은 카드(담은 순서)도 포함한다. 앱을 나갔다 들어오면 상태별로 복원한다: 카드를 담는 중이면 담은 카드 상태와 마지막으로 보던 카드 위치(카드 선택 화면), 보딩패스 상태(담은 카드 저장 후 [출발하기] 전)이면 보딩패스 화면, 시작 후(IN_PROGRESS)이면 담은 카드 순서대로 진행 지점부터 복원한다. 카드를 담는 중이거나 보딩패스 단계에서 만료 시각을 넘기면 담은 카드는 폐기하고 노선은 미완주(EXPIRED)로 종료하며, 시작 전 만료는 방문으로만 기록한다. 새 서비스일에는 새 노선을 생성한다.
- 출력: 기사 화면
- 예외: 진행 데이터 오류 시 마지막 정상 상태 사용. 만료된 노선은 이어보기 불가(미완주로 종료)하며 새 노선을 생성한다.
- 비고: -

## 컨디션

### RIDE-03 오늘의 컨디션 선택 `P0`
- 설명: 현재 컨디션을 선택해 오늘의 추천에 반영한다. 슬라이더가 아닌 곰돌이 캐릭터가 있는 카드 선택형으로 제공한다.
- 입력: 컨디션 값(맑음 / 보통 / 흐림 / 비 중 1개)
- 처리: 4가지 컨디션(맑음·보통·흐림·비, 예: SUNNY/NORMAL/CLOUDY/RAINY) 중 단일 컨디션을 선택하고 노선 생성 요청값에 포함한다. 선택한 컨디션은 노선(route)과 사용자 컨디션 이력(일자·컨디션·routeId)에 함께 저장한다. 컨디션 카드 4장(곰돌이 이미지 + 컨디션명)을 한 화면에 가로로 나열하고, 탭하면 해당 카드가 선택 상태로 표시된다(다른 카드 탭 시 선택 변경, 단일 선택). 각 카드에는 컨디션에 맞춰 어떻게 추천되는지 설명하는 툴팁(예: 컨디션별 난이도 구성 안내)을 제공한다. 선택된 카드는 테두리·체크 표시 등으로 명확히 구분한다. 컨디션은 난이도 비율만 조정하며 시간은 조정하지 않는다(RIDE-04). 후보 카드 풀(노선)은 컨디션을 선택하고 다음 단계로 넘어가는 시점에 생성한다. 노선은 서비스일당 1회만 생성하므로 생성 후에는 컨디션을 변경할 수 없으며, 컨디션 화면으로 다시 돌아오면 선택한 컨디션을 표시하고 '오늘 컨디션은 이미 정해졌어요' 안내를 노출한다(문구는 제안).
- 출력: 컨디션 값
- 예외: 미선택 시 다음 CTA 비활성화. 컨디션 이력 저장 실패는 노선 생성을 막지 않고 재시도한다.
- 비고: 컨디션 4종 단일 선택. 컨디션별 난이도 비율은 RIDE-04 참조. 이력은 추후 학습 기반 개인화의 기초 데이터. 툴팁 문구와 곰돌이 이미지는 디자인 확정 후 반영(화면설계서 참조).

## 기사 추천

### RIDE-04 오늘의 노선 생성 `P0`
- 설명: 이동시간·관심분야·컨디션을 기반으로 기사 묶음(노선)을 생성한다. 1차는 규칙 기반 랜덤 추출 방식이며, 컨디션별 난이도(HARD:EASY) 비율에 맞춰 기사를 선택한다. 노선은 서비스일당 1회만 생성할 수 있다. 추출된 기사는 '후보 카드 풀'로 제공하며, 사용자가 후보 카드를 좌우로 넘겨 보며 원하는 카드를 장바구니처럼 담아 노선을 구성한다(RIDE-08~10).
- 입력: userId, 이동시간(분), 관심분야(카테고리 ID 목록), 컨디션, 후보 기사(RSS-08 추천 가능 상태, 기사별 난이도 태그 포함)
- 처리:
  1. 노선 1회 제한: 노선은 서비스일(KST 자정 기준)당 1회만 생성할 수 있다. 진행 중 노선(CREATED·IN_PROGRESS, 만료 전)이 있으면 그 노선을 반환하고, 없더라도 오늘 서비스일에 이미 생성된 노선(완주·만료 포함)이 있으면 새로 만들지 않고 해당 노선을 반환한다. 연타·두 기기 동시 요청도 처음 생성된 노선을 반환한다.
  2. 목표 시간 T(분): 오늘(KST) 요일의 요일별 이동시간(MY-07)을 우선 사용하고, 요일별 설정이 없거나 0분(쉬는 날)이면 기본 이동시간(ONB-08/MY-05)을 사용한다. 쉬는 날에 요청이 와도 노선은 생성한다. 컨디션에 따라 목표 시간 T는 조정하지 않는다(시간 조정은 추후 검토).
  3. 후보 풀 구성: 후보 풀 = 추천 가능 상태 기사(RSS-08) ∩ 사용자 관심분야 카테고리. 모든 판단은 서비스일 하루 기준이며, 기사는 서비스일 당일에만 유효하므로 전일 이력(열람 여부 등)은 후보 풀에 사용하지 않는다. 후보는 기사에 배정된 난이도 태그(HARD/EASY, AI-01)별로 나눈다. 카테고리는 8개 서비스 카테고리 기준이다(RSS-07).
  4. 시간 조건: 선택 기사의 예상 읽기시간(RSS-09) 합계는 T×70% 이상, T×120% 이하여야 하며 목표는 T이다. 카드 담기 방식에서는 사용자가 담은 카드의 합계에 이 조건을 적용한다(RIDE-10).
  5. 컨디션별 난이도 비율(HARD:EASY, 기사 수 기준, 규칙 테이블): 맑음 3:2 / 보통 2:3 / 흐림 1:4 / 비 1:4. 컨디션은 난이도 비율만 조정한다. 이 비율은 시스템이 추천(후보 구성)할 때만 적용하며, 사용자는 난이도와 상관없이 원하는 카드를 자유롭게 담을 수 있다.
  6. 기사 선택: 현재 선택분의 난이도 비율이 목표 비율보다 부족한 쪽 난이도 풀에서 랜덤으로 1건씩 추출한다(동률이면 랜덤). 추가하면 누적 시간이 T×120%를 초과하는 기사는 건너뛰고 같은 풀에서 다시 추출한다. 해당 난이도 풀에 추가 가능한 기사가 없거나 누적 시간이 T 이상이 되면 선택을 종료한다.
  7. 확정: 누적 시간이 T×70% 이상이면 확정한다.
  8. 폴백 1 (T×70% 미달): 컨디션 난이도 비율을 해제하고, 관심분야 카테고리 안에서 조건이 맞지 않아 선택되지 않았던 기사(난이도 무관)를 랜덤으로 추가한다. T×120% 상한은 유지한다.
  9. 폴백 2: 그래도 T×70% 미만이면 준비된 기사만으로 그대로 확정한다(시간 미달 허용). 관심분야 밖으로는 후보를 확대하지 않는다.
  10. 후보 카드 풀 구성: [1]~[9]로 확정된 기사(추천 구성)에, 같은 관심분야·같은 난이도 비율 규칙(기사 수 기준)으로 보충 후보를 추가 추출해 후보 카드 풀을 만든다. 보충 후보 수는 추천 구성 기사 수만큼(풀 크기 약 2배)이며 설정값으로 관리한다. 풀의 카드 순서를 랜덤으로 섞어 순번을 부여하고, routeId와 함께 카드 목록·순서·기사별 난이도·컨디션을 스냅샷으로 고정 저장한다(상태 CREATED). 추천 구성 기사는 풀에 반드시 포함되므로 사용자가 이를 모두 담으면 시작 조건(RIDE-10)을 충족할 수 있다.
  11. 노선 생성 때마다 랜덤 추출하므로 서비스일이 다르면 동일 조건이라도 결과가 달라질 수 있다.
  12. 후보 수, 적용된 폴백 단계, 선택 결과를 추천 로그로 남긴다(RIDE-07). 사용자가 담은 카드와 시작 시점의 합계 시간도 함께 기록한다.
  13. 카드 탐색: 후보 카드는 좌우로 넘겨 가며 본다. 다음 카드는 오른쪽에서, 왼쪽으로 넘기면 이전 카드가 다시 보이는 책 넘김 방식이며, 순환하지 않고 첫 카드와 마지막 카드에서 끊긴다. 이미 담은 카드도 다시 넘겨 볼 수 있다(카드 클릭으로 담기·빼기: RIDE-09, 합계·시작 조건: RIDE-10).
  14. 노선 최종 구성은 사용자가 담은 카드로 이루어지며 순서는 담은 순서를 따른다. 담은 카드는 [시작하기] 시점에 저장되어 보딩패스에 표시되고(보딩패스에서 뒤로 가면 카드를 다시 고를 수 있다), 노선의 최종 고정과 운행 시작은 보딩패스의 [출발하기] 시점에 이루어진다(RIDE-06).
- 출력: routeId, 노선 상태, 추천 기사 목록(순번·articleId·난이도·예상 읽기시간), 총 예상 시간, 적용된 폴백 단계(0/1/2) , 후보 카드 풀(카드 순번·articleId·난이도·예상 읽기시간·추천 구성 여부), 풀 크기
- 예외: 선택 결과가 0건이면 노선을 생성하지 않고 '오늘 준비한 뉴스는 여기까지에요' 화면을 노출하며 방문으로만 기록한다(RIDE-05). T×70% 미달이어도 1건 이상이면 있는 기사로 그대로 제공한다. 추천 로그 저장 실패는 노선 생성을 막지 않고 재시도한다. 후보 카드 풀 전체를 담아도 합계가 T×70%에 못 미치면 그 상태로 시작할 수 있다(RIDE-10 폴백).
- 비고: 핵심 추천 로직. 1차는 규칙 기반 → 컨디션 이력·읽음 이력·추천 로그를 축적해 추후 학습 기반 개인화로 고도화. 난이도 비율과 허용 범위(70~120%)는 설정값으로 관리. 노선 상태(제안): CREATED(생성) → IN_PROGRESS(운행 시작, RIDE-06) → COMPLETED(완주, ARR-01) / EXPIRED(만료). 서비스일은 KST 자정 기준이며 노선은 생성일(서비스일) 다음 날 04:00에 만료 처리한다. 컨디션 조정은 난이도 비율(기사 수 기준)만 적용하며 시간 조정은 추후 추가한다. 난이도 비율은 추천(후보 풀 구성)에만 적용하고, 시작하기 조건은 시간 범위(T×70~120%)만 본다. 난이도 비율이 정수로 나누어 떨어지지 않으면 [6]의 '부족한 쪽 난이도 풀 우선 추출' 규칙을 따르며 최종 비율은 근사치(±1건)를 허용한다. 풀 크기 배수(2배), 난이도 비율, 허용 범위(70~120%), 집계 기준(30명) 등 설정값은 우선 서버 설정값으로 관리하고 어드민 화면 노출은 추후 검토한다.

### RIDE-07 노선 추천 로그 저장 `P0`
- 설명: 개인화 품질 검증과 추후 학습 기반 개인화를 위해 노선 생성 과정을 기록한다.
- 입력: routeId, userId, 컨디션, 이동시간(T), 관심분야, 후보 수(전체/난이도별), 적용된 폴백 단계, 선택 기사 및 난이도, 총 예상 시간 , 후보 카드 풀 크기, 사용자가 담은 카드·담은 순서, 시작 시점 합계 시간
- 처리: 노선 생성 시 입력 조건, 후보 수, 적용된 폴백 단계, 선택 결과를 추천 로그로 저장한다. 선택 결과가 0건인 경우도 로그로 남긴다. 시작하기 시점에 후보 카드 풀 대비 사용자가 담은 카드(기사·난이도·순서)와 합계 시간을 함께 기록해 추천 구성과 실제 선택의 차이를 분석할 수 있게 한다.
- 출력: 추천 로그
- 예외: 저장 실패 시 노선 생성은 계속 진행하고 로그만 재시도
- 비고: 컨디션 이력, 읽음 이력과 함께 추후 학습 기반 개인화의 기초 데이터. 로그 보관 기간 6개월(경과분 파기).

### RIDE-08 후보 카드 선택 화면 (좌우 넘기기) `P0`
- 설명: RIDE-04에서 구성한 후보 카드 풀을 좌우로 넘겨 보며 원하는 카드를 고르는 화면을 제공한다.
- 입력: routeId, 후보 카드 풀(카드 순번·articleId·제목·카테고리·난이도·예상 읽기시간·AI 한 줄 요약)
- 처리:
  1. 후보 카드는 한 장씩 노출하며 좌우 스와이프로 이동한다. 오른쪽으로 넘기면 다음 카드, 왼쪽으로 넘기면 이전 카드가 보이는 책 넘김 방식이다.
  2. 순환하지 않는다. 첫 카드에서 왼쪽으로, 마지막 카드에서 오른쪽으로 넘기면 더 이상 이동하지 않고 끊긴다.
  3. 각 카드에는 카테고리, 제목, 난이도, 예상 읽기시간, 담기 상태(담김/안 담김)를 표시한다. 카드를 클릭하면 담기·빼기가 된다(RIDE-09). 이미 담은 카드는 선택 상태로 명확히 구분한다.
  4. 현재 위치(n/전체)와 담은 카드 수·합계 시간은 화면 하단 장바구니 영역에 함께 표시한다(RIDE-10).
  5. 화면에 다시 들어오면(앱 종료 후 재진입 포함) 마지막으로 보던 카드 위치와 담은 카드 상태를 복원한다(RIDE-02).
  6. 스와이프와 클릭의 구분: 손가락 이동 거리가 임계값(제안 10px) 이상이면 스와이프, 미만이면 클릭(탭)으로 판정한다. 스와이프 중에는 담기·빼기를 처리하지 않는다.
- 출력: 후보 카드 화면(현재 카드, 담은 카드 수, 합계 시간)
- 예외: 후보 카드가 1장뿐이면 스와이프 없이 단일 카드로 표시한다. 후보 카드가 0장이면 '오늘 준비한 뉴스는 여기까지에요' 화면을 표시한다(RIDE-05).
- 비고: 신규. 스와이프로 이동하며 양 끝에서 끊긴다.

### RIDE-09 후보 카드 담기·빼기 (장바구니) `P0`
- 설명: 후보 카드를 장바구니처럼 담고 뺄 수 있다.
- 입력: routeId, articleId, 담기/빼기 액션(카드 클릭)
- 처리:
  1. 후보 카드를 클릭(탭)하면 해당 기사가 담은 카드에 추가되고 카드가 담김(선택) 상태로 표시된다. 담긴 카드를 다시 클릭하면 빼기가 된다. 담기에는 난이도 제한이 없다.
  2. 담은 순서를 기록하며, 이 순서가 운행 순서가 된다(RIDE-04 [14]).
  3. 담을 때마다 담은 카드 수와 합계 시간을 갱신한다. 합계 시간은 기사별 소수점 포함 저장값(RSS-09)을 합산한 뒤 합계를 올림하여 표시·판정한다. 카드별 표시값(올림)의 단순 합과 1분 차이가 날 수 있다.
  4. 담으면 합계가 T×120%를 넘기게 되는 카드는 담을 수 없다. 해당 카드는 담기 불가(비활성) 상태로 표시하고, 클릭 시 '분량이 넘어요' 안내를 노출한다.
  5. 담은 상태는 서버에 즉시 저장해 앱을 나갔다 들어와도 유지한다(RIDE-02).
- 출력: 담은 카드 목록(순서), 담은 카드 수, 합계 시간
- 예외: 저장 실패 시 화면의 담기 상태를 유지하고 재시도한다. 같은 카드를 연타해도 중복으로 담기지 않는다.
- 비고: 신규. 담기는 카드 클릭 방식이며, T×120% 초과 카드는 담기를 막는다.

### RIDE-10 시작하기 활성 조건 및 합계 시간 표시 `P0`
- 설명: 담은 카드가 기존 조건을 만족하면 하단 [시작하기] 버튼을 활성화한다.
- 입력: 담은 카드 목록, 목표 시간 T, 후보 카드 풀
- 처리:
  1. 활성 조건: 담은 카드의 예상 읽기시간 합계(RIDE-09 [3]의 합산·올림 기준)가 T×70% 이상, T×120% 이하이면 [시작하기]를 활성화한다(RIDE-04 [4]와 동일). 난이도 비율은 활성 조건에 포함하지 않는다(사용자는 난이도와 무관하게 담을 수 있다).
  2. 조건 미충족 시 버튼은 비활성이며, 부족/초과 시간을 안내한다(예: '약 N분 더 담아주세요'). 담기 단계에서 T×120% 초과는 막혀 있으므로(RIDE-09) 초과 안내는 발생하지 않는다. 담은 카드가 0장이면 버튼은 비활성이다.
  3. 폴백: 합계가 T×70%에 못 미치더라도 더 담을 수 있는 카드가 없으면 [시작하기]를 활성화한다. '더 담을 수 있는 카드가 없음'은 후보 카드 풀을 모두 담았거나, 남은 카드가 모두 T×120% 초과로 담기 불가인 경우를 말한다(RIDE-04 폴백 2와 동일한 취지). 이때 '더 담을 수 있는 카드가 없어요' 안내를 함께 노출한다.
  4. [시작하기]를 누르면 담은 카드·순서를 저장하고 보딩패스(RIDE-05)로 이동한다. 보딩패스에서 뒤로 가면 카드 선택 화면으로 돌아가 다시 고를 수 있다. 노선의 최종 고정과 운행 시작은 보딩패스의 [출발하기]에서 이루어진다(RIDE-06).
  5. 시작하기 버튼은 화면에서 가장 눈에 띄게 표시한다(디자인).
- 출력: 시작하기 활성 여부, 안내 문구, 합계 시간
- 예외: 시작 요청 실패 시 화면을 유지하고 재시도한다. 이미 시작된 노선에 중복 요청이 오면 기존 노선으로 이동한다.
- 비고: 신규. 난이도 비율은 추천(후보 풀 구성)에만 적용하고 시작 조건은 시간 범위만 본다.

## 보딩패스

### RIDE-05 보딩패스 표시 `P0`
- 설명: 생성된 오늘의 뉴스 노선을 탑승 전 요약한다. 후보 카드를 모두 담고 [시작하기]를 누르면 담은 카드 목록을 보여주는 보딩패스를 표시하고, 보딩패스의 [출발하기]로 운행을 시작한다.
- 입력: 노선 정보 , 담은 카드 목록(순서)
- 처리: 추천 기사 수, 예상 소요시간(선택 기사 예상 읽기시간의 합), 카테고리 및 유형별 목적지 정보를 표시한다. 추천 기사가 이동시간의 70%에 못 미쳐도 있는 기사 기준의 실제 예상 시간을 표시한다. [플로우] 후보 카드 선택(RIDE-08~09) → 모두 담음 → 시작하기 → 보딩패스(담은 카드 목록·기사 수·예상 소요시간 표시) → 출발하기 → 기사별 원문 보기 화면. 보딩패스의 담은 카드 목록은 담은 순서대로 표시한다. 보딩패스에서 뒤로 가면 후보 카드 선택 화면으로 돌아가 담은 카드를 유지한 채 다시 고를 수 있다(최종 고정은 [출발하기] 시점). 시작 화면에서는 기사 제목 바로 아래에 AI 한 줄 요약(AI-01)을 노출한다.
- 출력: 보딩패스
- 예외: 추천 기사 0건이면 보딩패스 대신 '오늘 준비한 뉴스는 여기까지에요' 화면을 표시하고 운행을 시작할 수 없다. 이 경우 방문으로만 기록하며 완주·스트릭에는 반영하지 않는다.
- 비고: 보딩패스 UI

### RIDE-06 뉴스 운행 시작 `P0`
- 설명: 보딩패스 확인 후 첫 번째 기사 읽기를 시작한다. 보딩패스의 [출발하기]로 시작한다.
- 입력: routeId, CTA (출발하기), 담은 카드 목록(담은 순서)
- 처리: 노선 시작 상태 및 시작 시각을 저장하고 첫 번째 기사로 이동한다. [출발하기]를 누르면 담은 카드·순서로 노선을 최종 고정하고 상태를 IN_PROGRESS로 바꾼 뒤, 첫 번째로 담은 카드의 기사 화면으로 이동한다. 각 기사 화면에서 [기사 보러가기]를 눌러 원문 URL로 이동하는 순간 다음으로 넘어가는 버튼이 활성화된다. 원문 링크가 깨졌거나 열리지 않아도 다음으로 넘어갈 수 있다('원문을 열 수 없어요' 토스트 후 버튼 활성화)(READ-02). 원문을 열었다가 앱으로 돌아오면 같은 기사 화면에 머물고 다음 버튼은 활성 상태를 유지하며, 자동으로 다음 기사로 이동하지 않는다.
- 출력: 첫 기사 화면
- 예외: 시작 실패 시 현재 화면 유지 및 재시도

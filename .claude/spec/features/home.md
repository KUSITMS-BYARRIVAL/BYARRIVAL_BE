## 홈

### HOME-01 오늘의 홈 조회 `P0`
- 설명: 사용자 정보와 당일 이용 상태를 기반으로 홈을 구성한다.
- 입력: 사용자 ID, 날짜
- 처리: 당일 노선, 기록, 에디터 픽 등을 조회하고 진행 중 노선이 있으면 이어보기 상태를 반영한다.
- 출력: 홈 데이터
- 예외: 일부 데이터 실패 시 영역 단위 오류
- 비고: -

### HOME-02 스트릭 표시 `P1`
- 설명: 사용자의 연속 서비스 이용 기록을 홈에 표시한다.
- 입력: 완주 기록
- 처리: 날짜별 완주 기록을 기준으로 연속 이용 일수를 계산한다.
- 출력: 스트릭
- 예외: 기록 없으면 초기 상태
- 비고: 완주 기준

### HOME-03 에디터 픽 미리보기 `P1`
- 설명: 홈에서 스몰토크 및 상식 용어 콘텐츠 일부를 제공한다.
- 입력: 에디터 픽 데이터
- 처리: 당일(서비스일) 노출 가능한 스몰토크(TALK-01 생성분)와 상식 용어 콘텐츠를 조회하여 일부를 카드 형태로 제공한다. 스몰토크 카드는 한 줄 + 이어서 + 연결 뉴스 칩으로 구성하며, 연결 뉴스 칩 탭 시 원문으로 이동한다.
- 출력: 콘텐츠 카드
- 예외: 콘텐츠가 없으면 해당 영역 미노출
- 비고: -

## 탑승 시작

### RIDE-01 뉴스 탑승 시작 `P0`
- 설명: 사용자가 오늘의 뉴스 이용을 시작한다.
- 입력: 탑승 CTA
- 처리: 오늘 서비스일의 노선 여부를 확인한다. 진행 중 노선(생성 또는 진행 상태이며 만료 전)이 있으면 기존 노선으로 이동하고, 오늘 이미 완주했거나 만료된 노선이 있으면 새 노선을 만들지 않고 해당 결과 상태로 이동한다. 오늘 노선이 없을 때만 컨디션 선택으로 이동한다. 전날 시작한 노선도 만료 시각(생성일 다음 날 04:00) 전이면 진행 중 노선으로 본다.
- 출력: 컨디션/기사 화면
- 예외: 노선은 서비스일당 1회만 생성 가능하며, 이미 노선이 있으면 신규 생성 대신 기존 노선으로 이동
- 비고: 핵심 CTA

### RIDE-02 진행 중 노선 이어보기 `P0`
- 설명: 중단했던 노선을 마지막 진행 지점부터 이어본다.
- 입력: routeId
- 처리: 노선 생성 시 고정 저장된 스냅샷(기사 목록·순서·기사별 배정 난이도) 기준으로 현재 기사와 진행 상태를 복원한다. 설정 변경이나 기사 유효기간(당일) 경과와 무관하게 노선 만료 시각(생성일 다음 날 04:00)까지 유지한다.
- 출력: 기사 화면
- 예외: 진행 데이터 오류 시 마지막 정상 상태 사용. 만료된 노선은 이어보기 불가(미완주로 종료)하며 새 노선을 생성한다.
- 비고: -

## 컨디션

### RIDE-03 오늘의 컨디션 선택 `P0`
- 설명: 현재 컨디션을 선택해 오늘의 추천에 반영한다.
- 입력: 컨디션 값(맑음 / 보통 / 흐림 / 비 중 1개)
- 처리: 4가지 컨디션(맑음·보통·흐림·비, 예: SUNNY/NORMAL/CLOUDY/RAINY) 중 단일 컨디션을 선택하고 노선 생성 요청값에 포함한다. 선택한 컨디션은 노선(route)과 사용자 컨디션 이력(일자·컨디션·routeId)에 함께 저장한다.
- 출력: 컨디션 값
- 예외: 미선택 시 다음 CTA 비활성화. 컨디션 이력 저장 실패는 노선 생성을 막지 않고 재시도한다.
- 비고: 컨디션 4종 단일 선택으로 확정. 컨디션별 난이도 비율은 RIDE-04 참조. 이력은 추후 학습 기반 개인화의 기초 데이터.

## 기사 추천

### RIDE-04 오늘의 노선 생성 `P0`
- 설명: 이동시간·관심분야·컨디션을 기반으로 기사 묶음(노선)을 생성한다. 1차는 규칙 기반 랜덤 추출 방식이며, 컨디션별 난이도(HARD:EASY) 비율에 맞춰 기사를 선택한다. 노선은 서비스일당 1회만 생성할 수 있다.
- 입력: userId, 이동시간(분), 관심분야(카테고리 ID 목록), 컨디션, 후보 기사(RSS-08 추천 가능 상태, 기사별 난이도 태그 포함)
- 처리:
  1. 노선 1회 제한: 노선은 서비스일(KST 자정 기준)당 1회만 생성할 수 있다. 진행 중 노선(CREATED·IN_PROGRESS, 만료 전)이 있으면 그 노선을 반환하고, 없더라도 오늘 서비스일에 이미 생성된 노선(완주·만료 포함)이 있으면 새로 만들지 않고 해당 노선을 반환한다. 연타·두 기기 동시 요청도 처음 생성된 노선을 반환한다.
  2. 목표 시간 T(분): 오늘(KST) 요일의 요일별 이동시간(MY-07)을 우선 사용하고, 요일별 설정이 없거나 0분(쉬는 날)이면 기본 이동시간(ONB-08/MY-05)을 사용한다. 쉬는 날에 요청이 와도 노선은 생성한다.
  3. 후보 풀 구성: 후보 풀 = 추천 가능 상태 기사(RSS-08) ∩ 사용자 관심분야 카테고리. 모든 판단은 서비스일 하루 기준이며, 기사는 서비스일 당일에만 유효하므로 전일 이력(열람 여부 등)은 후보 풀에 사용하지 않는다. 후보는 기사에 배정된 난이도 태그(HARD/EASY, AI-01)별로 나눈다.
  4. 시간 조건: 선택 기사의 예상 읽기시간(RSS-09) 합계는 T×70% 이상, T×120% 이하여야 하며 목표는 T이다.
  5. 컨디션별 난이도 비율(HARD:EASY, 기사 수 기준, 규칙 테이블): 맑음 3:2 / 보통 2:3 / 흐림 1:4 / 비 1:4.
  6. 기사 선택: 현재 선택분의 난이도 비율이 목표 비율보다 부족한 쪽 난이도 풀에서 랜덤으로 1건씩 추출한다(동률이면 랜덤). 추가하면 누적 시간이 T×120%를 초과하는 기사는 건너뛰고 같은 풀에서 다시 추출한다. 해당 난이도 풀에 추가 가능한 기사가 없거나 누적 시간이 T 이상이 되면 선택을 종료한다.
  7. 확정: 누적 시간이 T×70% 이상이면 확정한다.
  8. 폴백 1 (T×70% 미달): 컨디션 난이도 비율을 해제하고, 관심분야 카테고리 안에서 조건이 맞지 않아 선택되지 않았던 기사(난이도 무관)를 랜덤으로 추가한다. T×120% 상한은 유지한다.
  9. 폴백 2: 그래도 T×70% 미만이면 준비된 기사만으로 그대로 확정한다(시간 미달 허용). 관심분야 밖으로는 후보를 확대하지 않는다.
  10. 노선 구성: 확정된 기사의 순서를 랜덤으로 섞어 순번을 부여하고, routeId와 함께 기사 목록·순서·기사별 난이도·컨디션을 스냅샷으로 고정 저장한다(상태 CREATED).
  11. 노선 생성 때마다 랜덤 추출하므로 서비스일이 다르면 동일 조건이라도 결과가 달라질 수 있다.
  12. 후보 수, 적용된 폴백 단계, 선택 결과를 추천 로그로 남긴다(RIDE-07).
- 출력: routeId, 노선 상태, 추천 기사 목록(순번·articleId·난이도·예상 읽기시간), 총 예상 시간, 적용된 폴백 단계(0/1/2)
- 예외: 선택 결과가 0건이면 노선을 생성하지 않고 '오늘 준비한 뉴스는 여기까지에요' 화면을 노출하며 방문으로만 기록한다(RIDE-05). T×70% 미달이어도 1건 이상이면 있는 기사로 그대로 제공한다. 추천 로그 저장 실패는 노선 생성을 막지 않고 재시도한다.
- 비고: 핵심 추천 로직. 1차는 규칙 기반 → 컨디션 이력·읽음 이력·추천 로그를 축적해 추후 학습 기반 개인화로 고도화. 난이도 비율과 허용 범위(70~120%)는 설정값으로 관리. 노선 상태(제안): CREATED(생성) → IN_PROGRESS(운행 시작, RIDE-06) → COMPLETED(완주, ARR-01) / EXPIRED(만료). 서비스일은 KST 자정 기준이며 노선은 생성일(서비스일) 다음 날 04:00에 만료 처리한다.

### RIDE-07 노선 추천 로그 저장 `P0`
- 설명: 개인화 품질 검증과 추후 학습 기반 개인화를 위해 노선 생성 과정을 기록한다.
- 입력: routeId, userId, 컨디션, 이동시간(T), 관심분야, 후보 수(전체/난이도별), 적용된 폴백 단계, 선택 기사 및 난이도, 총 예상 시간
- 처리: 노선 생성 시 입력 조건, 후보 수, 적용된 폴백 단계, 선택 결과를 추천 로그로 저장한다. 선택 결과가 0건인 경우도 로그로 남긴다.
- 출력: 추천 로그
- 예외: 저장 실패 시 노선 생성은 계속 진행하고 로그만 재시도
- 비고: 컨디션 이력, 읽음 이력과 함께 추후 학습 기반 개인화의 기초 데이터. 로그 보관 기간 6개월(경과분 파기, 확정).

## 보딩패스

### RIDE-05 보딩패스 표시 `P0`
- 설명: 생성된 오늘의 뉴스 노선을 탑승 전 요약한다.
- 입력: 노선 정보
- 처리: 추천 기사 수, 예상 소요시간(선택 기사 예상 읽기시간의 합), 카테고리 및 유형별 목적지 정보를 표시한다. 추천 기사가 이동시간의 70%에 못 미쳐도 있는 기사 기준의 실제 예상 시간을 표시한다.
- 출력: 보딩패스
- 예외: 추천 기사 0건이면 보딩패스 대신 '오늘 준비한 뉴스는 여기까지에요' 화면을 표시하고 운행을 시작할 수 없다. 이 경우 방문으로만 기록하며 완주·스트릭에는 반영하지 않는다.
- 비고: 보딩패스 UI

### RIDE-06 뉴스 운행 시작 `P0`
- 설명: 보딩패스 확인 후 첫 번째 기사 읽기를 시작한다.
- 입력: routeId, CTA
- 처리: 노선 시작 상태 및 시작 시각을 저장하고 첫 번째 기사로 이동한다.
- 출력: 첫 기사 화면
- 예외: 시작 실패 시 현재 화면 유지 및 재시도
- 비고: -
